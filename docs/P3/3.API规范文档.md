
# 校园互助服务平台 — 核心 API 规范文档


## 1. 通用约定

### 1.1 基础信息

* Base URL: `/api`
* 认证方式: 除登录接口外，其余接口均需在请求头携带 JWT Token：`Authorization: Bearer <token>`
* Content-Type: `application/json`

### 1.2 HTTP 状态码约定

客户端及服务端需首先依赖 HTTP 状态码判断请求成败，具体业务错误再通过响应体 `code` 细化：

* `200 OK`：请求成功
* `201 Created`：资源创建成功（如发布需求、接单）
* `400 Bad Request`：参数校验失败、业务逻辑错误（如积分不足）
* `401 Unauthorized`：未登录或 Token 失效
* `403 Forbidden`：无权限访问（如越权查看他人订单）
* `404 Not Found`：资源不存在
* `429 Too Many Requests`：请求频率超限（触发防刷）
* `500 Internal Server Error`：服务端异常

### 1.3 统一响应格式

遵循架构文档 2.3.3 节规范：

```
成功响应：
json
{
  "code": 0,
  "message": "OK",
  "data": { ... }
}
失败响应：
json
{
  "code": 40001,
  "message": "具体错误原因",
  "data": null
}
分页响应：
json
{
  "code": 0,
  "message": "OK",
  "data": {
    "list": [ ... ],
    "page": 1,
    "pageSize": 20,
    "total": 134,
    "hasMore": true
  }
}
```

### 1.4 全局安全策略

* 防刷限流：`POST /auth/sessions` 连续失败 5 次将锁定对应 IP 15 分钟；写操作接口全局限流 30 req/min。
* XSS 防护：所有用户输入的文本参数（如 `title`, `description`, `comment`），服务端必须进行 HTML 实体转义后存储。
* 越权防护：所有涉及身份的操作（如评价、接单），需在服务端通过 JWT 提取操作人 ID，严禁前端显式传递用户 ID 参数。

## 2. 核心 API 详细设计

### 2.1 用户登录

* URL 路径: `/auth/sessions`
* HTTP 方法: `POST`
* 是否需认证: 否
* 成功 HTTP 状态码: `201 Created`

请求参数：

| 参数名    | 类型   | 必填 | 约束条件           | 说明                 |
| --------- | ------ | ---- | ------------------ | -------------------- |
| studentId | String | 是   | 长度 8-12 位纯数字 | 学号                 |
| password  | String | 是   | 最少 6 位          | SSO密码或OAuth授权码 |

响应格式：

```Plain
成功: 返回 Token 及用户脱敏基本信息（信用分等敏感数据需通过 GET /users/me 获取）
json
{
  "code": 0,
  "message": "OK",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "user": {
      "id": "u_001",
      "nickname": "西瓜同学",
      "avatarUrl": "/avatars/default.jpg"
    }
  }
}
失败:
json
{ "code": 10103, "message": "学号或密码错误", "data": null }
{ "code": 10102, "message": "账号因违规已被封禁", "data": null }
```

### 2.2 用户注册

> 说明：本系统以学校 SSO 统一认证为主登录方式。用户首次通过 SSO 登录时，系统自动创建本地账户并初始化默认昵称。本接口用于**非 SSO 场景下的本地学号注册**或 **SSO 绑定前的账户预创建** 。如仅支持 SSO，可关闭此接口并在文档中显式声明。

* URL 路径: `/auth/accounts`
* HTTP 方法: `POST`
* 是否需认证: 否
* 成功 HTTP 状态码: `201 Created`

请求参数：

| 参数名    | 类型   | 必填 | 约束条件                             | 说明                   |
| --------- | ------ | ---- | ------------------------------------ | ---------------------- |
| studentId | String | 是   | 长度 8-12 位纯数字                   | 学号，全局唯一         |
| password  | String | 是   | 最少 8 位，需包含字母和数字          | 登录密码               |
| nickname  | String | 是   | 长度 2-20 字符，不支持纯空格         | 用户昵称               |
| gender    | String | 否   | 枚举:`MALE`,`FEMALE`,`UNKNOWN` | 性别，默认 `UNKNOWN` |
| bio       | String | 否   | 最大长度 200 字符                    | 个人简介               |

响应格式：

```
成功: 返回创建的用户基本信息及 JWT Token
{
  "code": 0,
  "message": "OK",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "user": {
      "id": "u_001",
      "studentId": "20230001",
      "nickname": "西瓜同学",
      "avatarUrl": "/avatars/default.jpg",
      "gender": "UNKNOWN",
      "creditScore": 60,
      "pointsBalance": 0,
      "createdAt": "2026-05-15T10:00:00Z"
    }
  }
}

失败:
{ "code": 10104, "message": "该学号已被注册", "data": null }
{ "code": 10105, "message": "学号格式错误，应为 8-12 位数字", "data": null }
{ "code": 10106, "message": "密码强度不足，需至少 8 位且包含字母和数字", "data": null }
{ "code": 10107, "message": "昵称长度需在 2-20 字符之间", "data": null }
{ "code": 20102, "message": "内容包含违规敏感词，请修改", "data": null }
```

### 2.3 发布需求

* URL 路径: `/demands`
* HTTP 方法: `POST`
* 是否需认证: 是
* 成功 HTTP 状态码: `201 Created`

请求参数：

| 参数名           | 类型              | 必填     | 约束条件                                                     | 说明                                       |
| ---------------- | ----------------- | -------- | ------------------------------------------------------------ | ------------------------------------------ |
| title            | String            | 是       | 长度 2-50 字符                                               | 需求标题                                   |
| description      | String            | 是       | 最大长度 500 字符                                            | 详细描述                                   |
| category         | String            | 是       | 枚举: 快递代取,学习辅导,二手交易,活动组队,失物招领,咨询,其他 | 分类                                       |
| rewardType       | String            | 是       | 枚举: POINTS, FREE, CUSTOM                                   | 报酬类型                                   |
| rewardPoints     | Integer           | 条件必填 | 最小 1，最大 1000                                            | 悬赏积分数额（rewardType为POINTS时必填）   |
| customReward     | String            | 条件必填 | 最大长度 50 字符                                             | 自定义报酬说明（rewardType为CUSTOM时必填） |
| location         | Object            | 否       | -                                                            | 位置信息                                   |
| ├─ latitude    | Double            | 否       | -                                                            | 纬度                                       |
| ├─ longitude   | Double            | 否       | -                                                            | 经度                                       |
| ├─ description | String            | 否       | 最大 50 字符                                                 | 位置文字描述                               |
| deadline         | DateTime          | 否       | 必须晚于当前系统时间                                         | 期望完成时间                               |
| tags             | Array`<String>` | 否       | 数组长度最大 5，单标签长最大 10                              | 标签列表                                   |

响应格式：

```
成功: 返回创建的 DemandDTO

{

  "message": "OK",
  "data": {
    "id": "d_101",
    "publisherId": "u_001",
    "title": "求代拿快递到仙林7舍",
    "description": "中通快递，有点重...",
    "rewardType": "POINTS",
    "rewardPoints": 10,
    "customReward": null,
    "tags": ["快递代取", "急单"],
    "status": "OPEN",
    "deadline": "2026-05-05T18:00:00Z",
    "createdAt": "2026-05-04T10:00:00Z"
  }
}
失败:
json
{ "code": 60401, "message": "积分余额不足，无法发布悬赏", "data": null }
{ "code": 20102, "message": "内容包含违规敏感词，请修改", "data": null }
```

* URL 路径: `/demands`
* HTTP 方法: `GET`
* 是否需认证: 否（按距离排序时需认证）

请求参数：

| 参数名     | 类型    | 必填     | 约束条件                               | 说明                      |
| ---------- | ------- | -------- | -------------------------------------- | ------------------------- |
| page       | Integer | 否       | 最小 1，默认 1                         | 页码                      |
| pageSize   | Integer | 否       | 最小 1，最大 50，默认 20               | 每页数量                  |
| category   | String  | 否       | 同发布接口枚举                         | 按分类筛选                |
| rewardType | String  | 否       | 枚举: POINTS, FREE, CUSTOM             | 按报酬类型筛选            |
| keyword    | String  | 否       | 最大长度 50                            | 搜索关键词                |
| sortBy     | String  | 否       | 枚举: LATEST(默认), DEADLINE, DISTANCE | 排序方式                  |
| latitude   | Double  | 条件必填 | -                                      | 当 sortBy=DISTANCE 时必填 |
| longitude  | Double  | 条件必填 | -                                      | 当 sortBy=DISTANCE 时必填 |

请求参数：

| -------- | ------ | ---- | ------------- | ---------------- |

响应格式：

### 2.6 查看订单详情

* URL 路径: `/orders/{id}`
* HTTP 方法: `GET`
* 是否需认证: 是
* 权限控制: 服务端需校验当前登录用户是否为该订单的 `publisherId` 或 `helperId`，否则拒绝访问。

请求参数：

| 参数名 | 类型   | 必填 | 约束条件      | 说明             |
| ------ | ------ | ---- | ------------- | ---------------- |
| id     | String | 是   | 合法的订单 ID | 路径参数，订单ID |

响应格式：

```
成功: 返回包含关联数据的 OrderDTO
json
{
  "code": 0,
  "message": "OK",
  "data": {
    "id": "o_201",
    "demandId": "d_101",
    "publisherId": "u_001",
    "helperId": "u_002",
    "status": "WAIT_CONFIRM",
    "evidenceUrl": "/images/evidence_201_1.jpg",
    "createdAt": "2026-05-04T11:00:00Z",
    "updatedAt": "2026-05-04T14:30:00Z"
  }
}
失败:
json
{ "code": 30101, "message": "订单不存在", "data": null }
// HTTP 403: 无权查看他人订单 (code: 40301)
```

### 2.7 提交评价

> 架构安全性修正：评价属于订单的子资源，且评价人 ID 必须从 JWT 中提取以防越权伪造，因此 URL 调整为嵌套资源，移除前端 ID 传参。

* URL 路径: `/orders/{id}/reviews`
* HTTP 方法: `POST`
* 是否需认证: 是
* 成功 HTTP 状态码: `201 Created`
* 业务校验: 服务端需校验当前登录用户是该订单参与方，且订单状态为 `COMPLETED`，且未曾提交过评价。

请求参数：

| 参数名      | 类型    | 必填 | 约束条件            | 说明                     |
| ----------- | ------- | ---- | ------------------- | ------------------------ |
| id          | String  | 是   | 合法的订单 ID       | 路径参数，被评价的订单ID |
| rating      | Integer | 是   | 枚举: 1, 2, 3, 4, 5 | 评分星级                 |
| comment     | String  | 否   | 最大长度 200 字符   | 文字评价                 |
| isAnonymous | Boolean | 否   | 默认 true           | 是否匿名                 |

*(注：* *`reviewerId`** 和 **`revieweeId`** 由服务端根据路径 **`id`** 和 JWT 自动推导得出，前端不传)*

响应格式：

```
成功: 返回提交的 ReviewDTO
json
{
  "code": 0,
  "message": "OK",
  "data": {
    "id": "r_301",
    "orderId": "o_201",
    "reviewerId": "u_001", 
    "revieweeId": "u_002",
    "rating": 5,
    "comment": "非常准时，态度很好！",
    "isAnonymous": true
  }
}
失败:
json
{ "code": 50101, "message": "订单尚未完成，无法评价", "data": null }
{ "code": 50102, "message": "您已对该订单评价过，不可重复评价", "data": null }
{ "code": 50103, "message": "不能为自己评价", "data": null }
```

## 3. 错误码定义

遵循架构文档规定的 5 位数字规则：第1位业务域 + 第2位错误类型 + 后3位序号。

| 错误码 | 含义             | 对应业务域      | 说明                             |
| ------ | ---------------- | --------------- | -------------------------------- |
| 1xxxx  | 用户与认证模块   |                 |                                  |
| 10101  | 未登录或认证失败 | 1(用户)-0(认证) | Token 缺失、格式错误或已过期     |
| 10102  | 账号已被封禁     | 1(用户)-0(认证) | 用户状态为 BANNED，拒绝登录      |
| 10103  | 学号或密码错误   | 1(用户)-0(认证) | SSO 校验失败                     |
| 10104  | 学号已被注册     | 1(用户)-0(认证) | 该 studentId 已存在              |
| 10105  | 学号格式错误     | 1(用户)-0(认证) | 非 8-12 位纯数字                 |
| 10106  | 密码强度不足     | 1(用户)-0(认证) | 未满足最少 8 位且含字母数字      |
| 10107  | 昵称格式错误     | 1(用户)-0(认证) | 长度不在 2-20 字符范围内         |
| 2xxxx  | 需求模块         |                 |                                  |
| 20101  | 需求不存在       | 2(需求)-0(参数) | 查询的 demandId 无效             |
| 20102  | 包含违规敏感词   | 2(需求)-1(合规) | 标题或描述命中敏感词             |
| 3xxxx  | 订单模块         |                 |                                  |
| 30101  | 订单不存在       | 3(订单)-0(参数) | 查询的 orderId 无效              |
| 30102  | 需求已被接单     | 3(订单)-1(冲突) | 并发接单冲突                     |
| 30103  | 不能接自己的单   | 3(订单)-2(逻辑) | 发布者与接单者相同               |
| 30104  | 订单状态流转非法 | 3(订单)-2(逻辑) | 如对未完成订单进行确认           |
| 30105  | 需求已过期或下架 | 3(订单)-2(逻辑) | 接单时需求已不在 OPEN 状态       |
| 30301  | 无权查看该订单   | 3(订单)-3(权限) | 越权查看他人订单 (配合 HTTP 403) |
| 5xxxx  | 信用与评价模块   |                 |                                  |
| 50101  | 订单尚未完成     | 5(信用)-0(参数) | 对非 COMPLETED 状态订单评价      |
| 50102  | 重复评价         | 5(信用)-2(逻辑) | 同一订单已提交过评价             |
| 50103  | 不能给自己评价   | 5(信用)-2(逻辑) | 评价人与被评价人相同             |
| 6xxxx  | 积分模块         |                 |                                  |
| 60401  | 积分余额不足     | 6(积分)-4(业务) | 发布悬赏或兑换时余额不足         |

> ## 4. WebSocket / STOMP 实时通道
>
>
>
> OpenAPI 3.0 不原生支持 WebSocket，故单独说明（对应架构文档 §2.3.5、§2.3.6；需求 FR-N03、CI-02、NF-02、NF-06）。
>
>
>
> ### 4.1 连接
>
>

| 项   | 值                                              |
| --- | ---------------------------------------------- |
| URL | `wss://<host>/ws/chat`                         |
| 子协议 | STOMP 1.2                                      |
| 认证  | CONNECT 帧 Header `Authorization: Bearer <JWT>` |
| 异常  | 断开后客户端按指数退避重连（NF-06：1s → 30s）                  |

>
>
> ### 4.2 STOMP 路由
>
>

| 目的地                             | 类型        | 用途                   |
| ------------------------------- | --------- | -------------------- |
| `/topic/chat/{conversationId}`  | SUBSCRIBE | 订阅指定会话的双方消息          |
| `/topic/notifications/{userId}` | SUBSCRIBE | 订阅个人系统通知             |
| `/app/chat.send`                | SEND      | 客户端发送聊天消息            |
| `/user/queue/reply`             | SUBSCRIBE | 服务端定向回执（@SendToUser） |

>
>
> ### 4.3 消息体（STOMP body，JSON）
>
>
>
> #### 发送（客户端 → 服务端）
>
>
>
> ```json
> {
>   "conversationId": "conv_abc123",
>   "content": "你好，我可以去取快递",
>   "contentType": "TEXT"
> }
> ```
>
>
>
> #### 推送（服务端 → 客户端）
>
>
>
> ```json
> {
>   "type": "CHAT_MESSAGE",
>   "payload": {
>     "id": "msg_001",
>     "conversationId": "conv_abc123",
>     "senderId": "user_001",
>     "content": "你好",
>     "contentType": "TEXT",
>     "timestamp": "2026-05-17T10:30:00Z"
>   }
> }
> ```
>
>
>
> `type` 枚举：`CHAT_MESSAGE | NOTIFICATION | SYSTEM`。

> ## 6. 与设计一致性说明
>
>
>
> * **DTO 字段** 来源于 `docs/P2/3.架构设计文档.md` §2.3.7 与 `docs/P3/1.~2.类图2.0.md`，并补充乐观锁字段 `version`（Demand / Order）、`ConversationMember`、`Tag/DemandTag`、`isRead` 等 v6 评审结果。
>
> * **积分操作** 对外仅暴露 `transactions` / `exchange` / `balance`，扣减 / 转账 / 退款 / 兑换的具体实现由后端策略模式（`DeductStrategy / TransferStrategy / RefundStrategy / ExchangeStrategy`）封装，不暴露至 API。
>
> * **争议创建** 不暴露独立的 `disputes` 写接口，统一由 `POST /orders/{id}/dispute` 触发，符合 `StandardDisputeFactory` 的封装。
>
> * **状态机** 在 `OrderService.transition` 内集中校验，所有状态变更接口共享同一套合法转换图（见架构文档 §1.6）。
>
> * **认证** 所有非 `security: []` 标记的接口均要求 `Bearer <JWT>`；JWT 由 `AuthService.login` 签发，Spring Security 在 Filter / ChannelInterceptor 中统一校验。
>

> ## 4. 安全问题
>
>
>
> ### 4.1 越权风险（严重）
>
>
>
> * **评价接口**：`POST /reviews` 通过 body 接收 `orderId`，缺少对 `reviewerId/revieweeId` 必须由 JWT 派生的强约束。
    >
    >   * **P3 修正方案：** `POST /orders/{id}/reviews`，嵌套子资源 + 注明"reviewer/reviewee 由服务端从路径 id 和 JWT 自动推导，前端不传"。
>
> * **订单详情**：`GET /orders/{id}` 未声明权限校验，也未列出 `403` 响应。
    >
    >   * **P3 要求：** 服务端必须校验当前用户是否为该订单的 `publisherId` 或 `helperId`。
>
>
>
> ### 4.2 缺登录防爆破/限流约定
>
>
>
> * P3 §1.4 明确规定：
    >
    >   * `POST /auth/sessions` 连续失败 5 次将锁定对应 IP 15 分钟。
>
>   * 写操作接口全局限流 30 req/min。
>
> * AI文档：仅在错误码表中挂了 `40101 打招呼次数超限`，但没有在任何端点上挂 `429` 响应或限流说明。
>
>
>
> ### 4.3 XSS 防护未显式约束
>
>
>
> * P3 §1.4 要求服务端对所有用户输入文本字段（`title`、`description`、`comment` 等）进行 HTML 实体转义后存储。
>
> * AI文档：仅在系统级 NF-14 中一笔带过，未在 API 约定中体现。
>
>
>
> ### 4.4 登录态错误响应语义模糊
>
>
>
> * `POST /auth/login` 的 `401` 响应未区分"未登录/Token 失效"与"账号已封禁"两种语义；客户端无法精准做出"跳登录页"或"展示封禁原因"的选择。
>
>
>
> ### 4.5 HTTP 状态码语义弱化
>
>
>
> * 资源创建统一返回 `200`，丧失了 `201/429` 等状态码的语义信号。
>
> * 影响：Axios 等客户端的全局拦截器（如 401 跳转登录、429 退避重试）会失效。
>
